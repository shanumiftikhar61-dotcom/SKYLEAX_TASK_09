# Skyleax Admin Dashboard

A secure, responsive administration dashboard for managing user records. The React application and authenticated API run together on Cloudflare Workers, with Cloudflare D1 providing persistent SQLite storage.

## Features

- Password-protected administrator access, with PBKDF2 password hashing and expiring, revocable `HttpOnly` sessions.
- One-time administrator bootstrap restricted to `shanumiftikhar61@gmail.com` and a server-only setup token.
- Role-aware user record creation, viewing, editing, and deletion, with input validation and duplicate-email handling.
- Server-side text search, role/status/activity/date filters, stable sorting, and bounded pagination.
- Database-calculated dashboard summaries, registration trends, role and status charts, and an audit log.
- Responsive overview, user-management, activity, profile, and authentication screens.
- Same-origin checks, login throttling, secure response headers, prepared SQL statements, and database constraints.

## Technology

- React 19, TypeScript, Vite, Chart.js
- Cloudflare Workers and D1
- Vitest with the Cloudflare Workers test runtime

## Local development

Requirements: Node.js 20.19+ and npm.

1. Install the project dependencies:

   ```sh
   npm install
   ```

   If you change bindings or deployment settings in `wrangler.jsonc`, refresh the checked-in Worker binding types with `npx wrangler types`.

2. Create a local bootstrap secret. In PowerShell:

   ```powershell
   $token = node -p "require('node:crypto').randomBytes(32).toString('base64url')"
   Set-Content -Path .dev.vars -Value "ADMIN_BOOTSTRAP_TOKEN=$token"
   Set-Clipboard -Value $token
   ```

   `.dev.vars` is ignored by Git. Paste the token into the first-run setup form, then clear it with `$token = $null; Set-Clipboard -Value ""`. Never publish or commit the token.

3. Apply the local database migrations, then run the app:

   ```sh
   npx wrangler d1 migrations apply skyleax-task-09 --local
   npm run dev
   ```

4. Open the local URL printed by Vite. On first visit, use the displayed administrator email, your local setup token, and a new password of at least 12 characters. The setup token is not the administrator password.

Local D1 data persists in `.wrangler/`. To clear the local administrator and records, stop the server and remove only the local D1 state using Wrangler's documented local database workflow; the administrator bootstrap is intentionally single-use for a populated database.

## Environment and secrets

| Variable | Required | Purpose |
| --- | --- | --- |
| `ADMIN_EMAIL` | Yes | The authorized bootstrap address; configured as `shanumiftikhar61@gmail.com`. |
| `ADMIN_BOOTSTRAP_TOKEN` | First setup only | A high-entropy secret used once to create the first administrator. Local development uses `.dev.vars`; production uses a Cloudflare Worker secret. |

`ADMIN_EMAIL` is an application setting, not a password. Do not put credentials in `wrangler.jsonc`, source code, or a committed `.env` file. After the administrator is created, the bootstrap endpoint refuses another setup. The administrator chooses their own password; no password is supplied or generated by this project.

## Database

Cloudflare D1 stores:

- `users`: unique email, role, account status, timestamps, and a password hash for the administrator account.
- `sessions`: hashed session-token identifiers, administrator references, and expiration times.
- `activities`: registration, update, deletion, and administrator sign-in audit events.
- `login_attempts`: hashed sign-in identifiers and short-lived lockout state.

Schema changes live in `migrations/`. Local and remote D1 databases use the same migrations. Passwords and raw session tokens are never stored in the database.

## API

All management endpoints require an active administrator session cookie. JSON mutations must be same-origin. Error responses use `{ "error": "..." }`.

| Method | Endpoint | Purpose |
| --- | --- | --- |
| `GET` | `/api/health` | Worker health check. |
| `GET` | `/api/auth/status` | Check whether first-admin setup is required and configured. |
| `POST` | `/api/auth/setup` | One-time bootstrap using the configured email, setup token, and chosen password. |
| `POST` | `/api/auth/login` | Sign in and create a secure eight-hour session. |
| `GET` | `/api/auth/me` | Return the authenticated administrator profile. |
| `POST` | `/api/auth/logout` | Revoke the current session and clear its cookie. |
| `GET` | `/api/dashboard` | Database-backed summary cards, chart series, and recent activities. |
| `GET` | `/api/users` | Search/filter/sort/paginate user records. |
| `POST` | `/api/users` | Create a non-administrator account. |
| `GET` | `/api/users/:id` | Read a user record. |
| `PUT` | `/api/users/:id` | Validate and update a user record. |
| `DELETE` | `/api/users/:id` | Delete a non-administrator record. |
| `GET` | `/api/activities?limit=50` | Read recent audit events. |

`GET /api/users` supports `search`, `role`, `status`, `active`, `from`, `to`, `sort`, `direction`, `page`, and `pageSize`. Sort fields are `name`, `email`, `role`, `status`, and `createdAt`. Filters are combined server-side. Page size is limited to 100 and activity limits to 50.

## Cloudflare deployment

This project is structured for Cloudflare Workers + D1. Deployment requires access to a Cloudflare account; it has not been deployed unless you complete and verify these steps:

1. Authenticate with Cloudflare: `npx wrangler login`.
2. Create the production D1 database: `npx wrangler d1 create skyleax-task-09`.
3. This project’s `wrangler.jsonc` is already configured with its production database ID. For a separate copy or environment, replace it with that database’s ID.
4. Apply migrations with `npx wrangler d1 migrations apply skyleax-task-09 --remote`.
5. Deploy the application:

   ```sh
   npm run deploy
   ```

   This publishes the dashboard; first-admin setup remains disabled until its secret is configured.

6. Generate and set a one-time bootstrap secret in PowerShell:

   ```powershell
   $token = node -p "require('node:crypto').randomBytes(32).toString('base64url')"
   Set-Clipboard -Value $token
   npx wrangler secret put ADMIN_BOOTSTRAP_TOKEN
   ```

   Paste the secret from the clipboard when Wrangler prompts. Open the deployed site, refresh it, and paste the same token into the setup form. Choose your own administrator password (at least 12 characters). The account is not created until you complete that form. Then clear `$token` and the clipboard; optionally remove the one-time Worker secret with `npx wrangler secret delete ADMIN_BOOTSTRAP_TOKEN`.

The deployed application is available at the `workers.dev` URL printed by Wrangler. Until you set the bootstrap secret and complete the setup form, no administrator account exists and protected dashboard APIs correctly reject requests.
